Why this project

I play the clarinet in my town's municipal band and in the Diocesan Choir and Orchestra of Jaén. In music ensembles a lot of the organising runs on scattered messages, spreadsheets and memory. I want to build a tool designed for them, based on what I see every week from the inside.

I'm building it from scratch, without a template, so I have to make and justify every design decision: the data model, the API and the app experience.

How I'm building it

PartTechnologyPurpose

I keep a project log with decisions and progress, and I'll be moving it here and to the repository.

Work plan

  1. Analysis. What ensembles need and what the first version should do.
  2. Design. Data model and API contract.
  3. Backend. FastAPI API on PostgreSQL, with tests.
  4. App. Flutter client connected to the API.
  5. Testing and report. Validation with real use and writing up the project.
